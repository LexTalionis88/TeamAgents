# Глоссарий и инварианты предметной области

> Статус: начальная версия. Технические проекты уже есть, но предметная область
> ещё не определена, поэтому бизнес-термины и инварианты нельзя достоверно
> сформулировать без выдумывания. Не подменять их терминами .NET или MCP.

## Как использовать документ

Перед изменением доменной логики агент должен проверить этот документ и обновить
его, если меняются определения терминов или ограничения системы.

## Технические термины

- **MCP server** — отдельный процесс, который через stdout/stderr protocol
  предоставляет discoverable tools клиенту.
- **Typed workflow contract** — record, являющийся входом/выходом конкретного
  executor-а; свободный текст не является межагентным контрактом.
- **Escalation** — управляемый возврат workflow к Architect или Developer по
  решению PolicyManager, а не произвольный вызов инструмента.

Предметная область пока не определена. Для новых бизнес-терминов указывай:

- **Термин** — краткое определение без реализации.
- **Границы** — что входит в понятие и что к нему не относится.
- **Связи** — связанные сущности, состояния и события.

## Инварианты системы

### MCP boundary

- **Формулировка:** `McpServer` не зависит от `AgentClient`, а stdout сервера
  используется только MCP transport.
- **Почему важен:** сохраняет независимость протокола и корректность stdio.
- **Ответственный компонент:** `src/McpServer/Program.cs` и архитектура solution.
- **Что может нарушить:** ссылка сервера на клиент или диагностический `Console.WriteLine` в stdout.

### Typed handoff

- **Формулировка:** результат executor-а передаётся следующему executor-у через
  ожидаемый typed record; JSON должен соответствовать схеме результата.
- **Почему важен:** исключает скрытую передачу свободного текста между агентами.
- **Ответственный компонент:** `TypedAgentRunner`, `WorkflowContracts.cs`.
- **Что может нарушить:** изменение record без обновления producer/consumer или обход `RunAsync<T>`.

### Requirements and architecture gate

- **Формулировка:** Developer не меняет требования/архитектуру без
  `NeedsClarification=true` и `ArchitectureQuestion`; Architect не пропускает
  непринятые требования.
- **Почему важен:** запрещает молчаливое изменение задачи.
- **Ответственный компонент:** `EscalatingWorkflow.ValidateImplementation` и
  `ValidateArchitecture`.
- **Что может нарушить:** новый переход, обход runtime validation или изменение
  prompt без соответствующего контракта.

### Bounded retries

- **Формулировка:** число эскалационных циклов ограничено
  `WORKFLOW_MAX_CYCLES` диапазоном 0–3; бесконечные повторы запрещены.
- **Почему важен:** защищает workflow от бесконечного retry.
- **Ответственный компонент:** `AgentClientOptions` и `EscalatingWorkflow`.
- **Что может нарушить:** новый retry без `EnsureCycleAvailable` или снятие clamp.

### Security architecture challenge

- **Формулировка:** переход Security -> Architect возможен только при
  `SecurityReview.ArchitectureChallenged=true`; Architect обязан вернуть новый
  `ArchitectureDecision` до продолжения workflow.
- **Почему важен:** security finding не теряется и не превращается в молчаливое
  продолжение небезопасной схемы.
- **Ответственный компонент:** `SecurityReview`, `ManagerDecision` и
  `EscalatingWorkflow`.
- **Что может нарушить:** разрешение маршрута по одному имени агента,
  игнорирование `ArchitectureRevisionRequest` или обход лимита циклов.

### Short URL invariants

- **Формулировка:** `OriginalUrl` принимается только как абсолютный `http` или
  `https` URI; `Code` уникален; истёкшая ссылка не redirect-ит.
- **Почему важен:** предотвращает небезопасные схемы перенаправления, коллизии и
  доступ к ссылкам после истечения срока.
- **Ответственный компонент:** `ShortUrlApplicationService` и unique index в
  `ShortUrlDbContext`.
- **Что может нарушить:** запись напрямую в Redis, обход application service,
  удаление unique index или проверка expiration только на уровне cache TTL.

### Инвариант: _название_

- **Формулировка:** _какое условие всегда должно выполняться._
- **Почему важен:** _какую бизнес-ошибку или потерю целостности предотвращает._
- **Ответственный компонент:** _модуль, aggregate, сервис или граница данных._
- **Что может нарушить:** _конкретный пример изменения кода, схемы или API._

## Правило обновления

Любое изменение архитектуры, доменных терминов или инвариантов должно обновлять
соответствующий раздел этого документа в том же изменении.
