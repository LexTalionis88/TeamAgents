# Контекст продолжения работы с агентами

Дата фиксации: 23 сентября 2026 года.

## Основная цель

Дать .NET-команде агентов полноценную задачу и после постановки требований не
вмешиваться в предметную реализацию. Manager должен сам разбить задачу на
небольшие срезы, выбрать роли и запустить цикл Architect → Developer → Tester →
Security → Reviewer с ограниченными review/fix-циклами. Developer должен менять
workspace только через MCP, а итог должен опираться на фактические изменения и
проверки.

Эталонная проверка — реализация LikeService или Short URL service с ASP.NET
Core, PostgreSQL, Redis, Docker, тестами и документацией. В текущей проверке
используется LikeService.

## Зафиксированный порядок моделей OpenRouter

Порядок проверки уже зафиксирован в
`docs/ai/decisions/openrouter-free-model-selection.md`:

1. `google/gemma-4-26b-a4b-it:free`.
2. `dots-studio/dots-3-note-preview:free`.

Модель нужно задавать явно через `OPENROUTER_MODEL`, не использовать случайный
маршрутизатор `openrouter/free`.

Результаты последнего повторного прогона:

- Gemma получила от OpenRouter ответ `429 Too Many Requests` на шаге Manager.
- Dots успешно прошла Manager и Architect, но Developer остановился после
  чтения большого контекста и не выполнил MCP-патч.
- Полная автономная реализация LikeService пока не подтверждена.

## Tuzi API

Планируется подключить `https://api.tu-zi.com` как отдельного OpenAI-compatible
провайдера, не переименовывая и не перегружая OpenRouter-адаптер.

Рекомендуемые переменные окружения:

```text
MODEL_PROVIDER=tuzi
TUZI_API_KEY=<секрет только в окружении>
TUZI_BASE_URL=https://api.tu-zi.com/v1
TUZI_MODEL=<точный идентификатор модели>
```

Токен нельзя добавлять в исходники, README, memory bank, git или выводить в
логи. На момент фиксации `TUZI_API_KEY` и `API_KEY` в текущем процессе не были
заданы. В проекте ещё нет `TuziChatClientProvider`; его нужно добавить отдельным
классом и подключить через существующую фабрику провайдеров.

## Текущее состояние workspace

- AgentClient, McpServer и общий workflow не изменялись последним прогоном.
- Незакоммичены два изменения:
  - этот контекстный документ;
  - ранее созданный агентом частичный `src/LikeService/LikeService.csproj`.
- Частичный `.csproj` не следует исправлять вручную, если цель — проверить
  автономность агентов. Исправления должен выполнить Developer через MCP.
- Коммиты и push в рамках этого продолжения не выполнялись.

## Правила следующей сессии

- Все комментарии, промпты и документация — на русском.
- Поставщики моделей должны быть изолированы в собственных классах; логика
  `AgentClientApplication` не должна знать детали конкретных API.
- Интерфейсы и реализации должны находиться в разных папках.
- Не изменять AgentClient, McpServer и workflow при решении предметной задачи.
- Перед изменениями прочитать `AGENTS.md` и необходимые документы memory bank.
- После подключения Tuzi проверить наличие MCP tool calls, фактический patch,
  restore/build/test и отсутствие изменений в защищённых проектах.
